# /brief-outsourcing

## 目的
通过一系列追问，把"帮我写个外包需求"变成一份供应商拿到就能开工的标准化文档。

## 输入
用户说"我需要外包做XX"。

## 执行流程

### Phase 1: Grilling（结构化追问）
逐项确认：

1. **供应商**：漫画（星光工作室）/ 设计（独立设计师陈）/ 视频（动画师赵）/ 其他？
2. **交付物**：具体是什么？（立绘/漫画页/海报/PV/社媒物料）
3. **规格**：尺寸、分辨率、格式、数量？
4. **用途**：最终用在哪个平台/场景？
5. **风格参考**：有没有对标参考图？没有的话需要提供吗？
6. **预算**：有没有预算范围？
7. **Deadline**：什么时候需要？

### Phase 2: 生成需求文档
根据回答填充标准化模板（结构参考 CONTEXT.md 的外包供应商信息）：

```
═══════════════════════════════════
玄策/玄机IP 外包需求文档
需求编号: XUANCE-{日期}-{序号}
发起日期: {今天}
需求截止: {Deadline}
═══════════════════════════════════

一、需求概述
二、交付物清单（含规格/数量）
三、IP风格参考（链接 moodboard + 对标图）
四、内容简要（叙事背景 + 核心信息 + 必须/禁止元素）
五、技术要求（格式/色彩/图层/精度）
六、时间节点（初稿 → 反馈(48h) → 修改 → 终稿）
七、验收标准 checklist
八、预算与付款节点
```

### Phase 3: 验收 Checklist 定制
根据交付物类型生成具体验收项：
- 漫画/立绘：角色造型一致性、比例、水墨技法
- 设计物料：平台尺寸适配、色彩规范、排版标准
- 视频：分镜还原度、时长、字幕、配乐

### Phase 4: 风险提示
- 如果 deadline 距离今天 < 5 个工作日 → ⚠ 标注"时间紧张，建议加急"
- 如果预算低于 CONTEXT.md 中的供应商常规报价 → ⚠ 标注"预算可能不足"

## 护栏
- 所有参考图链接必须可访问（死链要标注）
- 外包速览文档必须在 Obsidian 中可访问
- 供应商接单前必须回复"已阅"确认
- 修改轮次上限 3 轮
