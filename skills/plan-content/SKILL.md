# /plan-content

## 目的
在动笔之前，通过结构化追问，把模糊的"想发点什么"变成一份可执行的内容简报。

## 输入
用户说"帮我排下周内容"或类似请求。

## 执行流程

### Phase 1: Grilling（追问澄清）
逐项确认以下信息（如果用户已提供则跳过）：

1. **目标平台**：B站 / 微博 / 小红书 / 公众号？还是全平台？
2. **本周IP节点**：有没有角色生日、PV发布、联动活动、节假日借势？
3. **可用素材**：本周有哪些新素材？（立绘/漫画页/视频/概念图）
4. **上周回顾**：上周哪个内容类型数据最好？哪个最差？
5. **特殊约束**：预算限制？人手限制？竞品避让？

### Phase 2: 生成排期
参考 CONTEXT.md 中的平台参数（频率/最佳时间），生成7天×4平台的内容排期表：

```
| 日期 | B站 | 微博 | 小红书 | 公众号 | 备注 |
```

排期规则（来自 CONTEXT.md）：
- B站视频固定周四/周五 18:00
- 工作日微博 2-3条/天，周末减半
- 小红书每日 1 条
- 公众号周二/周四 21:00

### Phase 3: 缺口检查
- 是否有连续2天以上某平台空白？
- 是否有连续3条同类型内容？
- 重要节点前3天是否安排了预热？

### Phase 4: 输出内容简报
对每条排期输出：
- 内容标题（临时）
- 内容类型
- 所需素材（如果没有 → 标注"待制作"）
- 预期数据（基于历史同类内容估算）

## 护栏
- 不凭空编造素材 —— 没有素材就标注"待制作"并通知制作团队
- 同一平台同一天不超过 3 条
- 如果用户说"随便排"，必须追问至少 3 个问题再动手
